# zapolnyaka-en

Автозаполнялка уровней для движка Encounter ([en.cx](https://en.cx)). Читает набор конфигов (игра + уровни + коды) и раскладывает их в `LevelEditor` через Playwright — тело задания, коды, бонусы, сектора, подсказки, автопереход, название уровня, условие прохождения.

Браузер запускается **не headless** — можно наблюдать и при необходимости вмешаться.

---

## Go-версия (рекомендуется)

Go-версия — самодостаточный бинарь без зависимостей: не нужны Node.js, yarn, Playwright. Работает на Windows, macOS и Linux. Имеет интерактивное TUI-меню и CLI-режим.

### Скачать

Перейди на страницу [Releases](https://github.com/zawert879/zapolnyka-en-/releases) и скачай бинарь для своей платформы:

| Платформа | Файл |
|---|---|
| Windows 64-bit | `zapolnyaka-windows-amd64.exe` |
| macOS (Intel) | `zapolnyaka-darwin-amd64` |
| macOS (Apple Silicon) | `zapolnyaka-darwin-arm64` |
| Linux 64-bit | `zapolnyaka-linux-amd64` |

На macOS/Linux после скачивания сделай файл исполняемым:

```bash
chmod +x zapolnyaka-darwin-arm64
```

### Первый запуск

**Без аргументов** — открывается интерактивное TUI-меню:

```bash
./zapolnyaka
```

TUI само спросит логин, пароль и путь к `game.yml` при первом использовании.

### CLI-режим

Если нужна автоматизация или скрипты — передай аргументы напрямую:

```bash
# Сохранить учётные данные (однократно)
zapolnyaka auth <логин> <пароль>

# Залить все уровни из game.yml
zapolnyaka go data/game.yml

# Проверить конфиги без браузера
zapolnyaka validate data/game.yml

# Сравнить конфиг с тем, что уже залито на en.cx
zapolnyaka check data/game.yml
```

Учётные данные хранятся локально в `.zapolnyaka.json` (рядом с бинарём). Последний использованный `game.yml` запоминается — следующий раз путь можно не указывать:

```bash
zapolnyaka go   # использует последний game.yml
```

## CLI

### `go <game>` — залить всё

Залить все уровни из `game.yml`/`game.json` последовательно, в одном браузере и одной сессии.

```bash
yarn dev go data/game.yml
```

### `assets <game>` — залить ассеты (только Go-версия)

Залить файлы из папки ассетов в раздел «Файлы для игры» en.cx (`FileUploader.aspx`). После загрузки они раздаются с `https://d1.endata.cx/data/games/<gameId>/<файл>` (мгновенно) и `https://cdn.endata.cx/...` (кэш 24 ч). Лимит — 48 МБ на файл.

```bash
zapolnyaka assets data/game.yml      # или пункт меню «🖼 Залить ассеты» в TUI
```

- Папка по умолчанию — `assets/` рядом с `game.yml`; переопределяется полем `assetsDir` в game-конфиге.
- Заливаются все обычные файлы из папки (без подпапок и скрытых файлов).

#### UUID-имена и плейсхолдеры `{{...}}`

Файлы заливаются под случайными **UUID-именами** (`design.css` → `7f3a…b2.css`), чтобы игроки не могли угадать/перебрать имена спойлерных ассетов. В контенте ссылаешься по читаемому имени через плейсхолдер, а `go` подставляет реальный URL:

```html
<style>@import url("{{design.css}}?v=1");</style>
<script src="{{fog.js}}"></script>
```
`{{design.css}}` → `https://d1.endata.cx/data/games/82460/7f3a…b2.css` (gid/домен больше не хардкодишь).

- Маппинг «имя → uuid» хранится в `assets/.manifest.json`; uuid **стабилен** (при повторной заливке переиспользуется, ссылки не ломаются). **Не удаляй манифест.**
- **Префикс `~`**: файл `~logo.png` заливается как `logo.png` (без uuid, `~` снимается) — для файлов, которые ок оставить с читаемым именем. Ссылаешься `{{logo.png}}`.
- Плейсхолдеры раскрываются в теле задания, task/help бонусов и текстах подсказок. Порядок: сначала `assets` (заливка + манифест), потом `go` (подстановка). Если `{{чего-то}}` нет в манифесте — `go` падает с понятной ошибкой.

### `ui <game>` — веб-интерфейс (только Go-версия)

Всё то же самое, что в TUI и CLI, но в браузере, плюс редакторы и эмулятор — в одном окне на `http://127.0.0.1:8090/ui/`:

```bash
zapolnyaka ui data/game.yml                  # откроет браузер
zapolnyaka ui --port 9000 --offline --no-open
```
В TUI — пункт «🖥 Веб-интерфейс». Слева — уровни игры (с чекбоксами для выборочной заливки) и ассеты, сверху — выбор игры из `data/*/game.yml` и вкладки:

- **Команды** — `go` (все или отмеченные уровни), `assets`, `validate`, `check`, `snapshot` (имя, код, pid), `auth`, создание игры; лог выполнения стримится в консоль, прогресс по уровням. Команды идут по одной.
- **Коды** — таблица `codes.yml` уровня: тип, сектор, бонус, ответы, время, `levels`, порядок; инспектор записи (task/help, ответы чипами), предупреждения (нет времени у бонуса, ответ виден в имени), кнопки «Ввести/откатить в эмуляторе». Сохранение переписывает файл (комментарии в YAML теряются) и проверяет его штатным загрузчиком.
- **Редактор** — `task.html` / `conf.yml` / `codes.yml` как текст (нумерация строк, Ctrl+S, вставка `{{ассетов}}`) и форма `conf.yml` справа: название, комментарий, автопереход и штраф, условие прохождения, clean, обычные и штрафные подсказки.
- **Превью** — контент уровня в дизайне игры без шапки движка (Desktop/Телефон, что показывать) и проверки: плейсхолдеры, `@import` вместо `<link>`, ответы в тексте задания или в именах.
- **Эмулятор** — та же побайтовая play-страница с dev-панелью во вкладке, «В новом окне», сверка со снимком реальной страницы (`snapshots/*.html`) прямо в интерфейсе.

Правки файлов уровня видны эмулятору и превью сразу. Сервер слушает только 127.0.0.1 и без пароля — не пробрасывайте его наружу без нужды.

### `emu <game>` — эмулятор play-страницы (только Go-версия)

Локальная копия страницы прохождения en.cx, **побайтово** повторяющая HTML движка (v1.88): тот же путь `/gameengines/encounter/play/<gid>/`, те же CSS/JS с world.en.cx, та же разметка истории, секторов, подсказок, штрафных подсказок, бонусов и таймеров (снята с реальной игры и сверена по 40 состояниям на 10 тестовых уровнях). Уровень берётся **из локальных конфигов** — тело задания, коды, подсказки, бонусы, автопереход. Правки `task.html`, `codes.yml`, `conf.yml` и файлов в `assets/` видны сразу: конфиги перечитываются на каждый запрос, открытая страница обновляется сама.

```bash
zapolnyaka emu data/game.yml                 # http://127.0.0.1:8090/gameengines/encounter/play/<gid>/ (откроет браузер)
zapolnyaka emu data/game.yml --port 9000 --no-open
zapolnyaka emu data/game.yml --offline       # CSS/JS движка из встроенной копии (без интернета)
zapolnyaka emu data/game.yml --dev           # шаблоны/статику читать с диска (правка без пересборки)
```
В TUI — пункт «🧪 Эмулятор уровней». В `game.yml` можно задать `title` (название игры в шапке) и `topic` (id темы обсуждения) — чисто для шапки эмулятора.

- Поведение как у движка: форма ответа POST'ит на тот же URL и получает страницу сразу (без редиректа) — неверный ответ остаётся в поле, сверху истории уведомление «Ответ или код верный/неверный», буквы неверного ответа обёрнуты в `<i>`; секторбонус даёт две записи истории; при прохождении уровня ответом приходит страница следующего уровня с записью «(N)»; уровень с одним сектором показывается без списка секторов; больше 10 секторов — три колонки; штрафная подсказка: ссылка `?pact=2&pid=` → страница подтверждения «Согласен/Отмена» → `?pact=1` открывает; таймеры подсказок и автоперехода — те же `new Timer(...)`, что перезагружают страницу по нулю; `?json=1` отдаёт модель уровня как движок.
- `{{плейсхолдеры}}` и ссылки `https://d1|cdn.endata.cx/data/games/<gid>/<файл>` подменяются на локальные файлы из `assets/` (по манифесту или по имени). Голые `<link …>` вырезаются из тела — как делает движок (текст `<link>` в комментариях не трогается).
- **Dev-панель** справа (свернуть/развернуть — кнопка или `Ctrl+`` `; живёт в Shadow DOM после `</html>`, в разметку страницы не вмешивается): выбор уровня; часы уровня, ползунок времени, пауза, «+1м/+5м/+10м» (подсказки и таймер автоперехода пересчитываются от времени уровня); список всех кодов уровня с чекбоксами «введён» (включая бонусы других уровней по `levels`); открытие штрафных подсказок; тумблер «переход на следующий уровень, когда задание выполнено»; сброс уровня / всей симуляции. `/play/<n>` — быстрый переход на уровень n.
- Состояние симуляции живёт в `<папка game.yml>/.emu-state.json` (переживает перезапуск). Логин в истории ответов берётся из сохранённых учётных данных.
- Не воспроизводится (нет в конфигах): блокировка ответов, сообщения организаторов, окно действия бонусов, финальная страница игры. Известное допущение: порог трёх колонок секторов (>10) снят с уровня на 12 секторов.

#### Снимки реальной страницы и сверка

Реальную play-страницу можно сохранить в `<папка game.yml>/snapshots/` и побайтово сравнить с эмулятором:

```bash
zapolnyaka snapshot data/game.yml --name L06-before                # GET текущего уровня команды (HTML + ?json=1)
zapolnyaka snapshot data/game.yml --name L06-wrong --send "мимо"    # страница-ответ на ввод кода
zapolnyaka snapshot data/game.yml --name L11-open --pid 2255048 --pact 2   # страница ?pid=&pact=
python go_app/internal/emu/tools/emudiff.py snapshots/L06-before.html http://127.0.0.1:8090/gameengines/encounter/play/82460/
python go_app/internal/emu/tools/replay.py snapshots/steps.txt      # повторить те же действия на эмуляторе и сравнить каждую страницу
```
`emudiff.py` маскирует только заведомо динамическое (случайные `rnd`/id таймеров, секунды отсчёта, id сущностей, время, uid, uuid-имена ассетов) и отрезает dev-панель. Формат `steps.txt` — в шапке `replay.py`. Не чаще пары запросов в секунду: en.cx отбивает частые запросы на `NotHumanRequest.aspx`, и сессия (в том числе браузерная) на несколько минут блокируется. Логин Go-клиента привязан к User-Agent — менять UA после логина нельзя.

Снять страницу можно и из браузера: при запущенном эмуляторе выполни на реальной странице содержимое `http://127.0.0.1:8090/emu/capture.js`, затем `EMU_CAPTURE('L06-before')` (страница POST'ит свой HTML и `?json=1` в `/api/snapshot`; Chrome может один раз спросить разрешение на доступ к localhost). Шаблон `templates/play.html` генерируется из снимка: `python go_app/internal/emu/tools/gen_template.py snapshots/L06-before.html` (нужен снимок уровня без секторов/подсказок/бонусов/таймера, но с телом).

### `game <path>` — создать `game.yml` / `game.json`

```bash
yarn dev game data/game.yml                      # шаблон с комментариями
yarn dev game data/game.yml -g 82006 -d rnd.en.cx
yarn dev game data/game.json -b                  # минимальный json
```

- Формат определяется по расширению (`.yml` / `.yaml` / `.json`).
- `-d, --domain` — домен (по умолчанию `tech.en.cx`).
- `-g, --gameId` — id игры (если не задан, поставится `0` — поправишь вручную).
- `-b, --bare` — минимум полей без комментариев.

### `level <game> <dir> [level]` — создать шаблон уровня

```bash
yarn dev level data/game.yml 11                # папка 11/, level=11
yarn dev level data/game.yml встреча 11        # папка встреча/, level=11
yarn dev level data/game.yml 5 -b              # без комментариев
yarn dev level data/game.yml 5 -f json         # json вместо yml
```

- `dir` — имя папки (любая строка без слэшей). Если `dir` числовой, он же используется как `level` — аргумент можно опустить.
- `level` — номер уровня в en.cx (обязателен, если `dir` не число).
- `-f, --format json|yml` — формат конфига (по умолчанию `yml`, или из `game.defaultFormat`).
- `-b, --bare` — минимальный шаблон без пояснительных комментариев.

Команда создаёт `dir/conf.*`, `dir/codes.*`, пустой `dir/task.html` и добавляет запись в `levels` в `game.*`.

## `game.yml` (глобальный конфиг)

```yml
domain: tech.en.cx
gameId: 81980
defaultFormat: yml      # опционально, формат по умолчанию для `level`
levels:
  - 1/conf.yml
  - 2/conf.yml
```

Логин/пароль — **только в `.env`**.

Пути в `levels` — относительно директории `game.*`. Форматы `.json` и `.yml` поддерживаются одновременно — парсер определяет по расширению.

## `conf.yml` (уровень)

```yml
# файлы
codes: codes.yml
body: task.html
clean: true                   # очистить уровень перед заливкой

# настройки уровня
level: 11
autopass: 1800                # автопереход через 30 мин (0 — выкл)
autopassPenalty: 300          # штраф +5 мин при AP
name: "Встреча"               # «Название уровня»
comment: "доезд 20 мин"       # «Комментарий к уровню»
sectorsToClose: 7             # «Условие прохождения»: 7 из N
hints:
  - time: 600
    text: "Подсказка 1"
penaltyHints:
  - time: 0
    text: "Спойлер"
    penalty: 300
    comment: "Откроется со штрафом 5 мин"
```

**Все временные поля — в секундах.**

Обязательны: `level`, `codes`. Остальное опционально.

## `codes.yml` (коды уровня)

Массив записей. Порядок = порядок создания в админке.

```yml
- type: сектор
  sectorName: "сектор 1"
  answers:
    - ответ1
    - ответ2

- type: бонус
  bonusName: "бонус хлеб"
  answers: [хлеб]
  time: 300                  # -5 минут
  task: 'Найди хлеб<br><img src="{{1.jpg}}">'   # txtTask — задание бонуса, видно ДО ввода
  levels: "1-10"             # на каких уровнях играет (без поля — только на этом)
  help: "молодец!"           # txtHelp — текст/HTML/<script>

- type: штраф
  bonusName: "ловушка кот"
  answers: [кот, кошка]
  time: 600                  # +10 минут

- type: секторбонус
  sectorName: "сектор 3"     # видно игроку сразу (список секторов)
  bonusName: "хлеб"          # видно игроку сразу (список бонусов)
  answers: [хлеб]
  time: 0
  help: "<script>alert(1)</script>"

- type: секторштраф
  sectorName: "обманка"
  bonusName: "ловушка"
  answers: [обманка]
  time: 300
```

### Типы

| Тип | Что создаёт |
|---|---|
| `сектор` | только сектор |
| `бонус` | только бонус (−время) |
| `штраф` | бонус с `negative` (+время) |
| `секторбонус` | сектор + бонус с тем же кодом |
| `секторштраф` | сектор + штраф с тем же кодом |

### Поля

| поле | для кого | смысл |
|---|---|---|
| `type` | все | см. таблицу выше |
| `sectorName` | опц., для типов с сектором | имя сектора — **видно игроку сразу** (в списке секторов на уровне) |
| `bonusName` | опц., для бонус/штраф | имя бонуса — **видно игроку сразу** (в списке бонусов на уровне) |
| `answers` | все | массив кодов (мин. 1) |
| `time` | всё кроме чистого сектора | секунды |
| `task` | бонусные | текст/HTML в `txtTask` — «Задание» бонуса, показывается **до ввода** кода (в списке бонусов уровня). Плейсхолдеры `{{ассет}}` раскрываются |
| `help` | бонусные | текст/HTML/JS в `txtHelp` — показывается **только после ввода** верного кода |
| `levels` | бонусные | на каких уровнях играет бонус (чекбоксы уровней в форме бонуса). Строка: `"7"`, `"1-10"`, `">10"`, `">=10"`, `"<5"`, `"<=5"`, `"2,4,6-8"`, `"все"`/`"*"`. Без поля — только текущий уровень. С полем свой уровень **не подразумевается** — включай его в спецификацию. Номера сверяются с реальными уровнями игры при заливке |

⚠ **`sectorName`, `bonusName` и `task` видны игроку ДО ввода кода.** Если содержат спойлер — задавай нейтральные значения (или пропусти — en.cx сгенерит дефолт). Единственное поле, которое не видно до ввода — `help`.

Мультиуровневый бонус (`levels` на 2+ уровня или `все`) виден в админке на каждом своём уровне. При `clean: true` следующих уровней в том же запуске `go` он **не удаляется** — утилита помнит ID бонусов, созданных в текущем запуске. При повторном запуске очистка любого из его уровней удалит его, и он будет создан заново.

### Лимиты en.cx (обходятся чанками автоматически)

- 10 ответов на сектор за один запрос
- 100 ответов на бонус за один запрос

## Что скрипт делает на каждом уровне

1. Открывает `LevelEditor`.
2. Если `clean: true` — удаляет всё: задания, бонусы, сектора, подсказки, сбрасывает AP.
3. Ставит `name` / `comment` (если заданы).
4. Ставит `autopass` / `autopassPenalty`.
5. Заливает `body` (тело задания).
6. Добавляет `hints` и `penaltyHints`.
7. Создаёт сектора / бонусы / штрафы из `codes`.
8. Ставит `sectorsToClose` (если задано) — **после** создания секторов.

Между действиями — паузы 500–2000 мс.

---

## Подводные камни

- Селекторы привязаны к **русской локали** en.cx — переключение интерфейса на другой язык сломает заливку.
- Браузер не headless (намеренно) — можно наблюдать или вмешаться.
- `help` может содержать `<script>` — движок его выполнит при вводе кода. Используется в квестах для связи с кастомным HTML в теле задания.
- `sectorName`, `bonusName` и `task` видны игроку **сразу** (в списках секторов и бонусов уровня) — не клади туда ответ. Только `help` показывается после ввода верного кода.
