# zapolnyaka-en

Автозаполнялка уровней для движка Encounter ([en.cx](https://en.cx)). Читает набор конфигов (игра + уровни + коды) и раскладывает их в `LevelEditor` через Playwright — тело задания, коды, бонусы, сектора, подсказки, автопереход, название уровня, условие прохождения.

Браузер запускается **не headless** — можно наблюдать и при необходимости вмешаться.

---

## Установка

```bash
yarn install
```

Создай `.env` в корне `zapolnyaka-en/` (пример — [.env.example](.env.example)):

```
EN_LOGIN=логин_или_id
EN_PASSWORD=пароль
```

`.env` уже в `.gitignore`.

## CLI

### `go <game>` — залить всё

Залить все уровни из `game.yml`/`game.json` последовательно, в одном браузере и одной сессии.

```bash
yarn dev go data/game.yml
```

### `game <path>` — создать `game.yml` / `game.json`

```bash
yarn dev game data/game.yml                      # шаблон с комментариями
yarn dev game data/game.yml -g 82006 -d rnd.en.cx
yarn dev game data/game.json -b                  # минимальный json
```

- Формат определяется по расширению (`.yml` / `.yaml` / `.json`).
- `-d, --domain` — домен (по умолчанию `tech.en.cx`).
- `-g, --gameId` — id игры (если не задан, поставится `0` — поправишь вручную).
- `-b, --bare` — минимум полей без комментариев.

### `level <game> <dir> [level]` — создать шаблон уровня

```bash
yarn dev level data/game.yml 11                # папка 11/, level=11
yarn dev level data/game.yml встреча 11        # папка встреча/, level=11
yarn dev level data/game.yml 5 -b              # без комментариев
yarn dev level data/game.yml 5 -f json         # json вместо yml
```

- `dir` — имя папки (любая строка без слэшей). Если `dir` числовой, он же используется как `level` — аргумент можно опустить.
- `level` — номер уровня в en.cx (обязателен, если `dir` не число).
- `-f, --format json|yml` — формат конфига (по умолчанию `yml`, или из `game.defaultFormat`).
- `-b, --bare` — минимальный шаблон без пояснительных комментариев.

Команда создаёт `dir/conf.*`, `dir/codes.*`, пустой `dir/task.html` и добавляет запись в `levels` в `game.*`.

## `game.yml` (глобальный конфиг)

```yml
domain: tech.en.cx
gameId: 81980
defaultFormat: yml      # опционально, формат по умолчанию для `level`
levels:
  - 1/conf.yml
  - 2/conf.yml
```

Логин/пароль — **только в `.env`**.

Пути в `levels` — относительно директории `game.*`. Форматы `.json` и `.yml` поддерживаются одновременно — парсер определяет по расширению.

## `conf.yml` (уровень)

```yml
# файлы
codes: codes.yml
body: task.html
clean: true                   # очистить уровень перед заливкой

# настройки уровня
level: 11
autopass: 1800                # автопереход через 30 мин (0 — выкл)
autopassPenalty: 300          # штраф +5 мин при AP
name: "Встреча"               # «Название уровня»
comment: "доезд 20 мин"       # «Комментарий к уровню»
sectorsToClose: 7             # «Условие прохождения»: 7 из N
hints:
  - time: 600
    text: "Подсказка 1"
penaltyHints:
  - time: 0
    text: "Спойлер"
    penalty: 300
    comment: "Откроется со штрафом 5 мин"
```

**Все временные поля — в секундах.**

Обязательны: `level`, `codes`. Остальное опционально.

## `codes.yml` (коды уровня)

Массив записей. Порядок = порядок создания в админке.

```yml
- type: сектор
  sectorName: "сектор 1"
  answers:
    - ответ1
    - ответ2

- type: бонус
  bonusName: "бонус хлеб"
  answers: [хлеб]
  time: 300                  # -5 минут
  help: "молодец!"           # txtHelp — текст/HTML/<script>

- type: штраф
  bonusName: "ловушка кот"
  answers: [кот, кошка]
  time: 600                  # +10 минут

- type: секторбонус
  sectorName: "сектор 3"     # видно игроку сразу (список секторов)
  bonusName: "хлеб"          # видно игроку сразу (список бонусов)
  answers: [хлеб]
  time: 0
  help: "<script>alert(1)</script>"

- type: секторштраф
  sectorName: "обманка"
  bonusName: "ловушка"
  answers: [обманка]
  time: 300
```

### Типы

| Тип | Что создаёт |
|---|---|
| `сектор` | только сектор |
| `бонус` | только бонус (−время) |
| `штраф` | бонус с `negative` (+время) |
| `секторбонус` | сектор + бонус с тем же кодом |
| `секторштраф` | сектор + штраф с тем же кодом |

### Поля

| поле | для кого | смысл |
|---|---|---|
| `type` | все | см. таблицу выше |
| `sectorName` | опц., для типов с сектором | имя сектора — **видно игроку сразу** (в списке секторов на уровне) |
| `bonusName` | опц., для бонус/штраф | имя бонуса — **видно игроку сразу** (в списке бонусов на уровне) |
| `answers` | все | массив кодов (мин. 1) |
| `time` | всё кроме чистого сектора | секунды |
| `help` | бонусные | текст/HTML/JS в `txtHelp` — показывается **только после ввода** верного кода |

⚠ **`sectorName` и `bonusName` видны игроку ДО ввода кода.** Если содержат спойлер — задавай нейтральные значения (или пропусти — en.cx сгенерит дефолт). Единственное поле, которое не видно до ввода — `help`.

### Лимиты en.cx (обходятся чанками автоматически)

- 10 ответов на сектор за один запрос
- 100 ответов на бонус за один запрос

## Что скрипт делает на каждом уровне

1. Открывает `LevelEditor`.
2. Если `clean: true` — удаляет всё: задания, бонусы, сектора, подсказки, сбрасывает AP.
3. Ставит `name` / `comment` (если заданы).
4. Ставит `autopass` / `autopassPenalty`.
5. Заливает `body` (тело задания).
6. Добавляет `hints` и `penaltyHints`.
7. Создаёт сектора / бонусы / штрафы из `codes`.
8. Ставит `sectorsToClose` (если задано) — **после** создания секторов.

Между действиями — паузы 500–2000 мс.

## Подводные камни

- Селекторы привязаны к **русской локали** en.cx — переключение интерфейса на другой язык сломает заливку.
- Браузер не headless (намеренно) — можно наблюдать или вмешаться.
- `help` может содержать `<script>` — движок его выполнит при вводе кода. Используется в квестах для связи с кастомным HTML в теле задания.
- `sectorName` и `bonusName` видны игроку **сразу** (в списках секторов и бонусов уровня) — не клади туда ответ. Только `help` показывается после ввода верного кода.
